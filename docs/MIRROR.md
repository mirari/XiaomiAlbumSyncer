# 网页管理的单向镜像

完整镜像 `ghcr.io/mirari/xiaomi-album-syncer:mirror-edge` 包含 XAS 网页、JVM 后端和镜像执行模块，
只需一个容器。镜像任务由 XAS 调度，不需要独立容器、配置文件或 agent。
首次发布为 linux/amd64；生产部署建议使用对应 `sha-<完整提交号>` 标签或 digest 固定版本。

## 实现与上游兼容

镜像直接调用原版 `TokenManager`、`XiaoMiApi.fetchAllAlbums`、`fetchAssetsByAlbumId` 和 `downloadAsset`。
认证、请求参数、分页、录音命名和下载签名沿用上游；Python 只负责本地基线与文件对账，
通过容器内部管道请求原版 API，不读取凭据或数据库，也不实现 HTTP 客户端。
共享列表接口增加业务错误/页面完整性检查，临时业务错误最多请求 4 次，间隔 2/4/8 秒。
扫描失败不提交删除；下载返回不可用时也停止镜像，保留可恢复数据。

## 在网页创建任务

1. 原账号页面维护小米账号与认证信息。
2. 定时任务 → 新建任务 → 同步模式选择“单向镜像（云端 → 本地）”。
3. 设置账号、独立目标目录、cron 表达式和时区。例如北京时间每天 03:00 为
   `0 0 3 * * ?`、`Asia/Shanghai`。
4. 默认“全部相册”包括相机与未来新增相册；关闭后使用任务中选定的相册。
   图片、视频、录音开关决定文件类型；指定相册模式中录音还需要选择录音相册。
5. 默认只生成报告。保存后可立即执行，展开任务查看进度、执行结果和变更清单。
6. 核对后关闭“仅生成报告”，再执行以建立基线并开始同步。

可在任务页面启用/停用定时计划、立即执行、编辑任务，以及停止本次镜像执行。
执行期间不允许编辑或删除任务，先停止执行再修改。停止立即终止本地工作进程，正在进行的原版 HTTP 请求结束或超时后任务才释放运行锁。任务展开区域显示最近 30 次镜像执行；
完整报告保存在状态目录，可从网页下载。原增量备份任务的行为及历史界面保持原样。
镜像模式暂不使用原通知模板、EXIF/文件时间改写或表达式路径规则，页面明确采用相册名/文件名。

## 数据与恢复

- 原 XAS 数据库不新增表，模式及选项存入原任务 config JSON；旧任务默认为增量备份。
- 镜像基线、进度、报告、隔离文件保存在 `MIRROR_STATE_DIR/<任务ID>/`。
  未配置时默认是数据库旁的 `mirror/`。该目录必须持久化，且不能位于照片扫描目录内。
- 数据库和状态目录都应备份。删除网页任务不会删除状态目录或照片，避免意外损失。
- 实际同步只管理已核验纳入基线的文件。首次接管前已经多余的本地文件不会自动清除。
- 日常同步以云端为唯一修改入口：云端 ID、路径、SHA1 未变的已校验文件直接复用基线，不读取本地属性或内容。本地单独修改/删除由手动完整校验发现；完整校验可由维护工具通过内部工作进程配置 `verify_local: true` 启用，网页暂不提供此开关。
- 下载完成并通过哈希校验后才替换；旧内容保留在 `data/quarantine/`。
  每次读取一轮完整云端文件快照，检查本地文件后在本轮处理删除/旧路径清理。快照完成后的云端变化由下次同步发现；扫描不完整或失败时不执行清理。
- 不永久删除隔离文件，没有自动过期。按报告核对后再手动恢复或清理。
- 执行不是全库原子事务。停止/失败前可能已有部分下载、替换或隔离；日志报告和隔离副本保留。
  不要仅据失败状态推断完全没有文件变化。
- 首次实际执行后范围、文件类型、账号和目录与状态绑定；修改这些范围时应新建任务并重新对账。
- 同一云照片属于多个相册时保留多条路径，不跨相册去重。不保证只改收藏等元数据能够被识别。
- 同一实例阻止同时运行目标目录重叠的任务；也不要让其他容器/工具同时写入镜像目录。
- 完整镜像用 JVM 后端调用内部 Python 工作进程；独立二进制或官方镜像不包含该执行模块。

## Compose 示例

```yaml
services:
  xiaomi-album-syncer:
    image: ghcr.io/mirari/xiaomi-album-syncer:mirror-edge
    restart: unless-stopped
    ports:
      - "8232:8080"
    environment:
      TZ: Asia/Shanghai
      MIRROR_STATE_DIR: /app/mirror-state
      MIRROR_STAGING_BASE: /app/storage/Backups/XiaomiAlbumSyncer/staging
    volumes:
      - ./db:/app/db
      - /your/storage:/app/storage
      - /your/mirror-state:/app/mirror-state
```

升级现有实例应保留数据库及照片挂载，先停止旧的同目录下载计划，再切换已验证的完整镜像。
不要同时启动两个实例访问同一数据库或照片目录。首次部署用报告模式验证挂载及账号。

临时文件默认位于状态目录内，可用 `MIRROR_STAGING_BASE` 指定按任务 ID 隔离的暂存根。
照片与暂存都放在同一容器挂载 `/app/storage` 下，才能保证同文件系统 rename；
两个独立 bind mount 即使来自同一块物理盘，也可能退回跨卷复制。
下载在暂存区校验一次，发布时直接移动；跨卷复制仅核对大小，不重复全量哈希。

## 变更清单预览与定位

点击变更数量可分页查看记录。JPEG、PNG、GIF、BMP 文件支持按需加载缩略图及放大预览；
不支持的格式仍可复制文件或文件夹路径。新增、修改、移动条目预览当前文件；
已隔离条目预览对应运行留下的副本。文件不存在时显示提示，历史清单不会自动消失。
“云端已移除”记录扫描结果，“已隔离”记录执行结果，同一文件可能同时出现。
隔离副本不会在下一次同步时自动永久删除，需要审核后手动清理。

可通过 `MIRROR_HOST_PATH_MAP` JSON 对象将容器路径映射为宿主机路径，例如：
`{"/app/storage":"D:\\mirari","/app/mirror-state/2/data/quarantine":"C:\\Downloads\\Xiaomi Cloud\\quarantine\\2"}`。
映射采用最长目录前缀，仅用于页面展示；未配置时显示容器路径。
复制文件夹路径后可粘贴到资源管理器地址栏，浏览器不会直接启动本地程序。
预览与路径查询均要求登录，且只允许读取任务清单记录内的文件。

## 构建与发布

`docker build -f docker/Dockerfile.full -t xas-full:test .`

`Full XAS image` 工作流先运行镜像安全测试，再构建前端、编译并测试后端。
PR 仅构建；主分支推送或手动运行使用内置 GITHUB_TOKEN 发布 GHCR，标签为 `mirror-edge`
及 `sha-<完整提交号>`。首次包可能默认私有，需要在包设置中改为 Public 才能匿名拉取。
同步上游成功后显式触发完整镜像及 E2E 工作流；源码/镜像更新不会自动切换现有 NAS 容器。

自动跟随上游使用普通 merge，只有回归测试、后端编译测试和前端构建通过才推进 main；冲突或失败会停止，并在 Actions 日志和运行摘要中记录原因，不自动覆盖 fork 功能。


### Fork 接入边界

镜像表单由 `MirrorFormOptions.vue` 管理，沿用上游任务向导及表单校验流程；
`useCronForm.ts` 与上游保持一致。镜像执行、基线、预览和变更清单在独立文件中维护。
云端列表仍调用上游 `XiaoMiApi`，仅在列表响应边界增加失败重试及完整性检查，
认证、扫码登录、请求构造、分页解析和下载实现均由上游提供。

上游的任务级 `syncMode`（FULL/TIMELINE/CURSOR）与兼容旧镜像任务的
`config.syncMode`（ADD_ONLY/MIRROR）用途不同：后者选择本地镜像执行器。
镜像接受普通目录和上游默认相册／文件名模板，在执行与预览入口解析为基线根目录。
数据库迁移和表单路径转换沿用上游，已有基线及照片位置不变；暂不支持任意自定义模板。
升级测试覆盖实际 SQL 迁移链，集成测试覆盖旧目录与新模板指向同一份照片。

任务调度、配置字段、任务行展示及 Native Image 元数据仍是必要接入点；
上游修改这些接口时仍需适配，不能保证所有升级均无冲突。
